## Create a new project

```
duxt create <project-name>
```

Options:
- `--mode=static` (default) — Static site, no server needed
- `--mode=server` — Full-stack with ORM and API routes
- `--template=minimal` (default) or `--template=full`
- `--directory=<path>` — Where to create the project

---

## Start development server

```
duxt dev
duxt dev --port 9090  # Custom port
```

Starts a hot-reload dev server (default port 8080). Watches for file changes and rebuilds automatically.

### Running multiple apps simultaneously

Use different ports for each app:
```
# Terminal 1
cd app1 && duxt dev --port 8080

# Terminal 2
cd app2 && duxt dev --port 9090
```

Each app uses 5 ports starting from the base port (proxy, api, jaspr, webdev, jaspr-proxy).

---

## Generate a page

```
duxt g page <path>
```

Examples:
```
duxt g page blog/[slug]
duxt g page Admin/Posts/edit    # Namespace-aware: creates lib/admin/posts/pages/edit.dart
```

Creates a page component at the specified route path with file-based routing.
Namespace support: use `Namespace/Module/page` format (uppercase first letter = namespace).

# Duxt Server Project Structure

```
my-app/
├── pubspec.yaml              # Dart dependencies (jaspr, duxt, duxt_orm, duxt_html)
├── duxt.yaml                 # Duxt configuration (mode: server)
├── tailwind.config.js        # Tailwind CSS configuration
├── web/

├── lib/
│   ├── main.dart             # App entry point — registers routes
│   ├── app.dart              # Root app component with DuxtApp
│   ├── pages/                # File-based routing (same as static)
│   │   ├── index.dart
│   │   └── blog/
│   │       ├── index.dart
│   │       └── [slug].dart
│   ├── layouts/
│   │   └── default.dart
│   ├── components/
│   │   └── header.dart
│   └── models/               # ORM models
│       └── post.dart         # Model with schema, relations
├── server/
│   ├── main.dart             # Server entry point — DuxtServer setup
│   └── api/                  # API route handlers

├── database/

    ├── bundle/               # Compiled server binary
    └── public/               # Static assets

## Start development server

```
duxt dev
duxt dev --port 9090  # Custom port
```

Starts a hot-reload dev server (default port 8080). Watches for file changes and rebuilds automatically.

### Running multiple apps simultaneously

Use different ports for each app:
```
# Terminal 1
cd app1 && duxt dev --port 8080

# Terminal 2
cd app2 && duxt dev --port 9090
```

Each app uses 5 ports starting from the base port (proxy, api, jaspr, webdev, jaspr-proxy).
