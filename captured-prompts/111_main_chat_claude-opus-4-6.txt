## Key JWT Best Practices

### 1. **Secure Secret Key Management**
Never hardcode your secret key in your code or store it in a publicly accessible location. Store your secure secret key securely, such as using environment variables or a reliable secrets manager.

### 2. **Token Expiration Strategy**
Access tokens should have a short expiration time, typically between 15 minutes to 1 hour, as they are used to access protected routes and should be short-lived to minimize damage in case of token theft. Refresh tokens should have a longer expiration time, typically between 1 day to 1 week.

### 3. **Refresh Token Rotation**
Use Refresh Token Rotation: Every time a refresh token is used, issue a new one and invalidate the old one, which limits the risk if a token is compromised.

### 4. **Token Storage**
HTTP-Only Cookies cannot be accessed by JavaScript, are protected from XSS, can use Secure + SameSite policies, and are ideal for browser-based apps, making this the most secure storage method for web apps.

### 5. **Token Revocation and Tracking**
Implement a revoke mechanism: Maintain a server-side blacklist or a database to track active/invalidated tokens, and ensure refresh tokens have a longer expiration but are carefully monitored for misuse. ### 6. **Enhanced Security Monitoring**
Regularly update JWT libraries to ensure you're protected against known vulnerabilities.

These practices align with modern security standards for 2025-2026, emphasizing stateless authentication while maintaining robust server-side controls.

## Key Differences

### Maintenance & Modern Support
jose is actively maintained, supports modern JavaScript (ESM, TypeScript), and aligns with web platform standards, making it the best choice for new projects requiring strong standards compliance. In contrast, jsonwebtoken remains stable and widely used, but development has slowed.

### Standards Compliance
JOSE is comprehensive and supports a wide range of JOSE standards (JWT, JWS, JWE, JWK) and requires advanced features like key management and encryption, making it well-suited for applications that need robust security features and compliance with various standards. Meanwhile, jsonwebtoken is a straightforward solution to create and verify JWTs and is lightweight and easy to use, making it ideal for projects that require basic JWT functionalities without the overhead of additional features.

### Encryption Support
A major differentiator is encryption: The jose library fully supports both JWT signing (JWS) and encryption (JWE), making it a more versatile choice for applications that require secure token transmission. However, jsonwebtoken does not natively support JWT encryption (JWE); it focuses primarily on signing and verifying tokens (JWS), and for encryption, developers would need to use additional libraries or implement custom solutions.

### Code Patterns
The jsonwebtoken library still uses legacy patterns like callbacks and CommonJS modules, which don't align with modern JavaScript projects. In contrast, jose is built with TypeScript from the ground up, providing intelligent autocompletion, type safety, and better developer experience.

### Cross-Platform Support
Jose is designed to work across various Web-interoperable runtimes including Node.js, browsers, Cloudflare Workers, Deno, Bun, and others.

## Recommendations

For new greenfield projects: Start with jose—it's future-proof, secure by default, and works everywhere. However, for existing Express apps using simple HMAC tokens: jsonwebtoken + express-jwt is battle-tested and sufficient.

I've found comprehensive information about JWT access token refresh token rotation patterns in Node.js. Here's what the search results show:

## Overview

Refresh token rotation is the practice of updating an access token on behalf of the user without requiring interaction (like re-authenticating).

## Key Concepts

**Token Expiration Strategy:**
When a user logs in, the authorization server provides two tokens: a short-lived access token (valid for 15–60 minutes) and a longer-lived refresh token (lasting 7–14 days).

**Rotation Approaches:**
Time-based rotation automatically rotates tokens after a certain period—for example, a token may be valid for 24 hours and then automatically replaced with a new one. Usage-based rotation rotates tokens based on how often they are used—for example, a token may be valid for 100 requests and then automatically replaced with a new one.

## Node.js Implementation Pattern

A Node.js token rotation function generates a new access token and refresh token pair, invalidates the old refresh token, and stores metadata with a family ID and hash of the previous token.

**Secure Storage:**
Store a SHA-256 hash, not the raw token, so a database leak does not give attackers the actual token string.

The refresh token goes to an HTTP-only cookie scoped to /api/auth/refresh, keeping the refresh token away from frontend code while still letting the browser send it to the refresh endpoint.

**Cookie Security Flags:**
Use httpOnly: true, secure: true in production, sameSite: 'strict', and a narrow path such as /api/auth/refresh to reduce XSS and CSRF risk.

## Security Best Practices

Destroy the old refresh token and issue a new one to prevent replay attacks. Token reuse detection is a security mechanism used to detect and prevent the reuse of a previously issued token because if an attacker obtains a valid token, they can use it to gain unauthorized access unless the token is detected and invalidated.
